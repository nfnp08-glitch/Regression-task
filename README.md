# Regression-task
Прогнозирование стоимости медицинского страхования!

## Описание проекта
Этот обучающий проект наглядно демонстрирует все этапы решения классической задачи регрессии в Data Science — от первичного анализа данных и предобработки признаков до подбора моделей, борьбы с дисбалансом классов и оценки качества.

## Цель
Цель проекта — на практике отработать полный цикл решения регрессионной задачи в Data Science: от анализа исходных данных и предобработки признаков до выбора и сравнения моделей, подбора способов борьбы с дисбалансом классов и интерпретации результатов.

## Задачи

Файл EDA.ipynb — база и первичный анализ:
* проверка качества данных и аудит на ошибки;
* изучение распределения признаков и таргета, анализ взаимосвязей;
* препроцессинг: обработка пропусков, кодирование категориальных переменных, унификация типов.

Файл baseline_tuning.ipynb — улучшения и валидация:
* построение базовой модели и расчёт метрик — фиксация стартового уровня качества;
* тестирование преобразований данных и новых признаков;
* оценка эффективности через кросс‑валидацию;
* отбор только тех улучшений, которые стабильно повышают метрики.

## Для кого
Проект носит обучающий характер — его цель не в достижении максимальной точности любой ценой, а в системном освоении типовых шагов и распространённых подводных камней при построении классификационных моделей.

!!!## Заключение!!!
`В рамках проекта была решена задача прогнозирования отклика клиентов на маркетинговую кампанию по привлечению депозитов. Для этого был реализован полный цикл построения ML‑решения: от предобработки данных и разведочного анализа (EDA) до подбора гиперпараметров и интерпретации результатов.

Был проведён сравнительный анализ четырёх моделей классификации: Logistic Regression, Decision Tree, Random Forest и LightGBM. Подбор гиперпараметров выполнялся с помощью RandomizedSearchCV с 5‑кратной стратифицированной кросс‑валидацией, что обеспечило корректную оценку качества на несбалансированных данных.

Наилучшие результаты показала модель LightGBM: ROC‑AUC на кросс‑валидации — 0.800, на отложенной тестовой выборке — 0.7911. Практически идентичные значения метрик свидетельствуют об отсутствии сильного переобучения и хорошей обобщающей способности модели.

С точки зрения бизнес‑метрик модель демонстрирует сбалансированную эффективность: для целевого класса (клиенты, склонные к отклику) достигнуты показатели recall = 0.64 и precision = 0.76. Это означает, что модель охватывает 64 % потенциально заинтересованных клиентов и направляет маркетинговые усилия с точностью 76 %, что обеспечивает разумный компромисс между охватом аудитории и эффективностью использования бюджета.

Важным наблюдением стало различное влияние балансировки классов на разные типы моделей: для одиночных алгоритмов (Logistic Regression, Decision Tree) настройка class_weight не давала прироста, тогда как для ансамблевых методов (Random Forest, LightGBM) она оказалась критически важной.

На основании полученных результатов в качестве финальной модели для прогнозирования отклика рекомендуется использовать LightGBM с подобранными гиперпараметрами.`
